# PRD — 동물기록 복구작전

- 프로젝트명: 동물기록 복구작전
- 영문 프로젝트명: Animal Record Recovery
- Repository: `animal-record-recovery`
- 대상: 초등학교 3학년
- 교과: 과학 — 동물의 생활
- 형식: 태블릿 우선 웹 기반 상호작용형 학습 게임
- 구조: 5 Stages / 총 10 Screens
- 화면 기준: 태블릿 가로형 16:9 우선, 반응형 웹
- 핵심 엔진: Phaser + Three.js + HTML/CSS/SVG
- 저장: 단원 자체 백엔드 필수 아님. 허브 연동 시 MissionResult 반환, 독립 실행 시 IndexedDB/LocalStorage 폴백
- 문서 버전: 1.0
- 작성일: 2026-08-24

---

## 1. 제품 한 줄 정의

동물의 **생김새·특징·사는 환경·생활 방식·생활용품 활용 기록이 뒤섞인 연구소**에서 학생이 직접 관찰하고, 분류 기준을 만들고, 환경과 특징의 관계를 근거로 설명하고, 마지막에는 동물의 특징을 활용한 생활용품을 설계·시험·수정하여 데이터를 복구하는 초등 3학년 과학 학습 게임.

## 2. 교육과정 근거

### [4과02-01]
여러 가지 동물을 관찰하여 특징에 따라 동물을 분류할 수 있다.

게임 반영:
- Stage 1: 3D 관찰 및 공통점·차이점 확보
- Stage 2: 학생이 분류 기준을 만들고 실제 분류
- 분류 기준의 객관성을 가상 연구원 결과 비교로 검증

### [4과02-02]
다양한 환경에 서식하는 동물을 조사하여 동물의 생김새와 생활 방식이 환경과 관련되어 있음을 설명할 수 있다.

게임 반영:
- Stage 3: 생태 환경을 탐색하며 환경·생김새·생활 방식 증거 수집
- Stage 3 후반: 증거 3종을 연결하여 관계 설명
- Stage 4: 일부 정보가 없는 미확인 동물을 증거를 선택하여 추론

### [4과02-03]
동물의 특징을 이용하여 일상생활에서 활용할 수 있는 생활용품을 설계하여 협력적으로 소통할 수 있다.

게임 반영:
- Stage 5: 생활 문제 선택 → 동물 특징 선택 → 기능 연결 → 제품 설계
- 설계 후 기능 점검 → 수정 → 결과 카드 생성
- QR/로컬 공유를 통한 친구 설명·비교 활동 지원

## 3. 콘텐츠 정확성 원칙

1. 동물의 이름을 맞히는 것보다 **관찰한 특징을 근거로 판단**하게 한다.
2. 포유류·조류·파충류와 같은 생물학적 분류 체계 암기를 본 단원의 핵심으로 사용하지 않는다.
3. “환경에 적응하기 위해 이렇게 변했다”와 같은 식의 **적응 개념을 본 단원의 핵심 개념으로 직접 가르치지 않는다.**
4. 표현은 “이 생김새와 생활 방식은 사는 환경과 어떤 관련이 있을까?”처럼 관계 설명 중심으로 구성한다.
5. 동물 사실 데이터는 정적 콘텐츠 데이터셋으로 관리하며, 출처 필드를 둔다.
6. 생성형 AI가 임의로 동물 특징이나 생태 사실을 생성하여 정답 데이터에 반영하지 않는다.
7. 생활용품 설계는 정답 하나를 고르는 문제가 아니라, **동물 특징이 실제 제품 기능에 반영되었는지**를 평가한다.

## 4. 벤치마킹 원칙

### 동물 분류 수업 자료
참고 요소:
- 대상 관찰
- 비슷한 점과 다른 점 찾기
- 적절한 분류 기준 세우기
- 분류 기준에 따라 나누기
- “빠른가요?”처럼 사람에 따라 결과가 달라지는 기준과 “날개가 있나요?”처럼 같은 결과가 나오는 기준 비교

재설계:
- 카드 분류를 그대로 복제하지 않고 **분류 기준 생성 → 가상 연구원 검증 → 기준 수정**으로 확장

### 동물 도감형 자료
참고 요소:
- 숲, 강·호수, 바다 등 환경별 동물 탐색
- 동물의 특징을 짧게 정리

재설계:
- 정적 카드 목록 대신 **생태 돔에서 직접 발견해야 도감이 열리는 구조**

### 동물 특징 생활용품 설계 자료
참고 요소:
- 동물 특징에서 생활용품 아이디어 얻기

재설계:
- 입력 몇 번으로 결과가 생성되는 흐름이 아니라 **문제 선택 → 특징 선택 → 기능 연결 → 조립/스케치 → 기능 점검 → 수정**

### AR 동물 활동
참고 요소:
- 실제 공간에서 입체 동물을 관찰하는 경험

재설계:
- MVP는 WebXR/AR을 필수 의존성으로 두지 않음
- 3D 관찰 화면과 선택적 카메라 관찰로 학습 목표를 안정적으로 달성
- AR은 브라우저·기기 지원 범위가 확정된 후 선택적 확장 기능으로 고려

## 5. 대상 학습자와 난이도 원칙

대상은 초등학교 3학년이다.

### 조작 난이도
- 한 화면에서 주요 조작 1~2개에 집중
- 아이콘만으로 의미를 추측하게 하지 않고 짧은 한글 안내 제공
- 드래그, 회전, 확대, 관찰핀, 선택, 스케치 등 조작은 직관적으로 구성

### 사고 난이도
유치원 수준의 단순 기능을 피하고 다음의 다단계 로직을 사용한다.
- 관찰 → 공통점/차이점 판단
- 기준 생성 → 분류 → 결과 검증 → 기준 수정
- 환경/생김새/생활 방식 증거 조합
- 제한된 정보 선택 → 추론 → 근거 제출
- 생활 문제 → 동물 특징 → 기능 → 설계 → 시험 → 수정

## 6. 세계관

동물 기록 연구소의 데이터 코어에 오류가 발생했다.

뒤섞인 항목:
- 동물의 생김새
- 관찰 특징
- 사는 환경
- 생활 방식
- 동물 특징을 활용한 기술

학생은 “동물 기록 복구 연구원”이 되어 5개의 기록 구역을 복구한다.

복구 구역:
1. 관찰 기록
2. 분류 기록
3. 환경 기록
4. 미확인 기록
5. 활용 기록

각 Stage 완료 시 데이터 코어 조각 1개가 복구되며, 최종 5개가 모두 복구되면 연구원 인증과 도감 결과가 열린다.

## 7. 전체 학습 흐름

관찰 → 비교 → 기준 생성 → 분류 → 기준 검증 → 환경 조사 → 환경·생김새·생활 방식 연결 → 제한된 증거 추론 → 동물 특징 활용 → 생활용품 설계 → 기능 점검 → 수정 → 공유

## 9. Screen 01 — 동물 기록 연구소

- 중앙: 깨진 생태 데이터 코어
- 주변: 5개 기록 구역 노드
- 상단: 제목, 전체 복구율
- 하단: 연구도감 / 진행기록 / 설정
- 최초 실행 시 Stage 1만 활성
- Stage 완료 시 다음 Stage 활성
- 완료 Stage 재플레이 가능

## 10. Stage 1 — 관찰 기록 복구

### Screen 02 — 생태 관찰 스캐너
목표: 3D 동물을 직접 회전·확대하며 특징을 발견한다.

추천 관찰 동물 초안:
- 개구리
- 게
- 고등어 또는 금붕어
- 벌
- 고라니
- 달팽이

조작:
- 한 손가락 드래그: 3D 동물 회전
- 두 손가락 핀치: 확대/축소
- 관찰 렌즈 버튼: 관찰 모드
- 부위 터치: 관찰핀 생성
- 선택적 카메라 모드: 주변 동물 또는 흔적 촬영 후 사진에 관찰핀

핵심 로직:
- 미션별 유효 관찰 증거를 확보해야 진행
- 잘못된 부위를 눌러도 생명 감소 없이 재관찰 힌트
- 카메라 권한이 없어도 3D 표본만으로 완료 가능

### Screen 03 — 비교 기록판
목표: 두 동물의 공통점과 차이점을 자신의 관찰 증거로 구성한다.

조작:
- Stage 1에서 확보한 증거카드 드래그
- 같은 점 / 다른 점 슬롯 배치
- 필요 시 다시 3D 관찰로 돌아가기

완료 조건:
- 공통점 증거 1개 이상
- 차이점 증거 1개 이상
- 실제 데이터와 일치

## 11. Stage 2 — 분류 기록 복구

### Screen 04 — 분류 게이트
목표: 학생 스스로 관찰 가능한 분류 기준을 만든 뒤 동물을 분류한다.

흐름:
1. 특징 키워드 선택
2. 질문형 기준 생성
3. 8~12마리 동물을 YES/NO 두 게이트에 드래그
4. 분류 누락 여부 확인

예시 기준:
- 날개가 있나요?
- 다리가 있나요?

완료 조건:
- 모든 동물을 중복 없이 분류
- 현재 기준에 따른 데이터 결과와 일치

### Screen 05 — 기준 검증실
목표: 분류 기준은 누가 사용해도 같은 결과가 나올 수 있어야 한다는 점을 이해한다.

핵심 시나리오:
- 연구봇이 “빠른가요?” 같은 모호한 기준 제안
- 가상 연구원 A/B/C의 결과 불일치
- 학생이 이유를 판단하고 기준 수정
- “날개가 있나요?”처럼 분명한 관찰 기준으로 재검증

성공 조건:
- 가상 연구원 결과가 일치하는 명확한 기준으로 수정

## 12. Stage 3 — 환경 기록 복구

### Screen 06 — 생태 돔
목표: 다양한 환경을 둘러보고 해당 환경에서 관찰할 동물을 발견한다.

구현: Three.js 기반 경량 3D 디오라마.

환경 구역 예:
- 숲과 들
- 강·호수
- 바다
- 건조한 곳
- 추운 곳

조작:
- 스와이프/드래그: 카메라 궤도 회전
- 선택적 DeviceOrientation: 태블릿 방향과 카메라 시야 연결
- 동물 발견 후 스캐너 조준

센서 폴백:
- 권한 거부 또는 미지원 시 드래그 탐색으로 완전 대체

### Screen 07 — 환경 관계 분석판
목표: 환경, 생김새, 생활 방식의 관계를 증거로 설명한다.

학생은 다음 3종 증거를 연결한다.
- 환경 증거
- 생김새 증거
- 생활 방식 증거

관련 없는 방해 카드 1~2개 포함.

출력 문장 예:
“이 동물은 [환경]에서 관찰되며, [생김새]와 [생활 방식]이 그 환경과 관련되어 있습니다.”

## 13. Stage 4 — 미확인 기록 복구

### Screen 08 — 미확인 기록 수사실
목표: 필요한 정보를 선택하고 제한된 증거로 동물을 추론한다.

로직:
- CASE당 조사 에너지 3개
- 단서 5종 중 3종만 열람 가능
- 단서: 발견 장소, 몸의 모습, 이동 모습, 발, 생활 장면
- 후보 동물 4종
- 최종 선택 후 “판단 근거 제출” 필수

성공 조건:
- 정답 동물 + 유효한 근거 2개 이상

## 14. Stage 5 — 활용 기록 복구

### Screen 09 — 동물 기술 설계실
목표: 동물 특징을 일상생활 문제 해결 기능으로 연결하고 생활용품을 설계한다.

단계:
1. 생활 문제 선택
2. 연구도감에서 동물 특징 선택
3. 특징과 기능 연결
4. 기본 제품 위에 부품 드래그
5. 터치/펜으로 추가 스케치
6. 제품 이름과 한 줄 설명 작성

### Screen 10 — 기능 시험실·최종 복구
목표: 설계가 실제 문제 해결 조건을 충족하는지 점검하고 수정한다.

점검 항목:
- 선택한 동물 특징이 설계에 보이는가?

## 17. 평가 설계

### [4과02-01]
- 특징을 실제로 관찰했는가
- 공통점/차이점 증거를 올바르게 골랐는가
- 적절한 분류 기준을 만들었는가
- 모든 동물을 기준에 따라 빠짐없이 분류했는가
- 모호한 기준을 수정할 수 있는가

### [4과02-02]
- 환경에서 적절한 동물을 조사했는가
- 환경·생김새·생활 방식 증거를 올바르게 연결했는가
- 제한된 증거로 타당한 판단을 했는가
- 정답뿐 아니라 근거를 제출했는가

### [4과02-03]
- 생활 문제와 동물 특징의 연결이 타당한가
- 선택한 특징이 설계품 기능에 실제로 반영되었는가
- 테스트 실패 후 수정했는가
- 최종 설계를 설명/공유했는가

## 18. UX 원칙

- 모든 핵심 버튼 최소 44~48 CSS px
- hover 전용 기능 금지
- 한글은 이미지에 굽지 않고 HTML/CSS/SVG 사용
- 색상만으로 정답/오답을 구분하지 않음
- 모션 감소 설정 제공
- 배경음악/효과음 개별 음소거
- 읽기 부담을 줄이되 사고 과정을 줄이지 않는다

## 19. 태블릿을 써야 하는 이유

- 3D 입체 관찰: 관찰 각도를 학생이 직접 선택
- 멀티터치: 확대·축소·회전
- 카메라: 실제 주변 동물/흔적 기록
- 자이로/스와이프: 환경 탐색
- 터치 드래그: 분류, 증거 조합, 설계 조립
- 펜 입력: 설계 스케치
- 즉시 시뮬레이션: 기준 검증과 설계 테스트
- QR/카메라: 친구 결과 공유
