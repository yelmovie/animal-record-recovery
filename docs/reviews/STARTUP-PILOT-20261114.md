# 동물기록 복구작전 — 첫 화면과 지도 장애 복구

2026-11-14 · 로컬 시범 빌드의 측정 및 검증 기록. 첫 화면과 지도를 필요할 때 불러오는 변경은 [`3b15f17`](https://github.com/yelmovie/animal-record-recovery/commit/3b15f178b39a11a37516bff57d2f3305c6addc85)에 반영됐고, 이후 변경과 함께 [운영 사이트](https://animal-record-recovery.yelsam.workers.dev/)에 배포됐다. 아래 수치는 당시 로컬에서 측정한 결과다.

첫 화면에서 타이틀 표시, 소리, 기존 기록 확인에 필요한 모듈만 미리 받는다. 기존 기록 판독을 유지하므로 형식 검사와 이전 버전 변환에 필요한 데이터 모듈도 포함된다. 인트로 플레이어는 시작이나 이야기 다시 보기를 누를 때, 지도와 활동 코드는 인트로를 나가거나 저장 기록으로 이어갈 때 받는다. 첫 화면에서 설정을 누르면 기존 설정을 열기 위해 앱을 준비한다.

| 측정 구간 | 일반 로컬 전 → 후 | 10Mbps·40ms·CPU 4배 감속 전 → 후 |
|---|---:|---:|
| 첫 콘텐츠 표시 | 44 → 24ms | 1.33 → 1.03초 |
| 첫 시작 버튼을 누를 수 있을 때까지 | 27 → 24ms | 1.34 → 1.04초 |
| 시작 버튼 → 인트로 건너뛰기 버튼 | 35 → 51ms | 54 → 145ms |
| 인트로 건너뛰기 → 지도 버튼 | 7 → 31ms | 28 → 712ms |
| 인트로 건너뛰기 → 지도의 이동 준비 | 24 → 48ms | 108 → 1,058ms |
| 지도에서 관찰의 숲 선택 → 첫 관찰 답변 버튼 | 16 → 14ms | 51 → 55ms |
| 첫 시작 버튼 이전 JS | 36 → 13개, 495,194 → 135,268바이트 | 동일 |

Chrome 1280×800, 같은 로컬 서버의 전후 빌드를 교대로 각 5회 실행한 중앙값. 매번 새 브라우저 컨텍스트, HTTP 캐시·서비스워커 차단, 걷기 시간과 영상 감상 시간을 분리하려고 모션 줄이기와 인트로 건너뛰기를 사용했다. 버튼 중앙을 실제로 클릭할 수 있을 때를 준비 시점으로 잡았다. JS 전송량은 로컬 서버 응답의 헤더 포함 값이다. 제한망에서 시작 버튼은 23% 빨라졌고 지도·활동 코드 일부를 받는 대기는 인트로 이후로 이동했다. 운영 환경이나 학교 실기기의 전후 수치는 아니다.

- 지도 길 데이터 요청을 차단하고 관찰의 숲으로 직접 들어갔다. 개구리의 몸 표면을 관찰하고 기존 학습 기록에 저장했으며, 새로고침해도 남았다. 길 데이터 차단을 해제하고 ‘다시 불러오기’를 눌러 지도와 정상 이동도 복구했다.
- 지도 모듈을 차단하면 ‘다시 불러오기’가 인트로 완료를 유지하며 지도에서 다시 시작했다. 지도 대표 그림만 차단해도 첫 활동이 열렸다. 첫 화면 파일을 막은 경우에도 ‘다시 열기’로 복구했다.
- 첫 화면에서 설정이 열리는지, 인트로를 재생해 끝났을 때 정상 지도에 도착하는지 확인했다.
- JavaScript 구문 검사와 단위 테스트 276개 통과. 브라우저 검증은 macOS Chrome, 1280×800과 터치 에뮬레이션 1024×768·915×515에서 진행했다. 실제 iPad Safari와 Android Chrome, 전체 활동 완주는 이번 작업에서 확인하지 않았다.
