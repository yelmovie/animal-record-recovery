# 운영 검증: 생태 돔 영상 로딩과 사진 촬영

2026-11-15(KST) · [운영 사이트](https://animal-record-recovery.yelsam.workers.dev/) · 검증한 앱 커밋: `818daf07a34ec3a40c7f9e77c0f6018d838995b3`

운영 교사용 미리보기에서 브라우저와 접속 경로를 바꿔 비교했다. 이 검증으로 학생 기록이나 앱 코드, 자동진행 로직을 변경하지 않았다.

| 조건 | 관찰 결과 |
| --- | --- |
| Chrome / Mac Wi-Fi, 무음 | 생태 돔 두 라운드에서 영상 6개 재생과 사진 6장 저장을 확인했다. 게 영상은 재생 요청 약 2.13초 후 시작했고, 학생 기록은 그대로였다. |
| Chrome / 5Mbps, 80ms 모의 연결 | 사진 6장이 저장됐다. 게 영상은 약 1.31초에 재생되기 시작했다. |
| Chrome / 이전 정지 사례 | 게 영상 요청 후 약 10.7초에 HTTP 206 응답이 관찰됐다. 재생 시간이 0:00에서 움직이지 않고 약 12초 뒤 앱이 다음 화면으로 넘어갔다. |
| WebKit / Mac Wi-Fi | 다른 실행에서 토끼 영상의 이어받기 요청은 HTTP 206 응답을 받았지만 전송이 끝나기 전에 취소됐고, 영상은 0:00에서 멈췄다. 별도 실행에서는 토끼 영상이 끝까지 재생됐지만 사진이 남지 않았다. |
| Cloudflare 외부 접속 경로 | 인천에서 게 단독 영상은 약 0.38초에 시작했다. 싱가포르에서는 영상 구간 요청 5건이 모두 성공했다. |

재생 전 정지는 첫 장면을 재생할 만큼 영상 데이터를 확보하기 전에 발생했다. 지연이 회선, CDN 경로, 브라우저의 미디어 요청 처리 중 어디서 시작되는지는 아직 확인하지 못했다. 제한한 속도에서 정상 재생된 사례도 있어 속도만으로는 설명하기 어렵다.

재생 후 촬영 실패는 별개로 확인했다. 같은 게·토끼 장면의 프레임 10개를 추출했을 때, 사용한 WebKit이 WebP 요청에 PNG를 반환했다. 폭 320px로 줄여도 모두 앱의 저장 한도(64,000자)를 넘었고, Chrome은 같은 10개를 모두 한도 안에 저장할 수 있는 WebP로 만들었다. 이 결과는 테스트한 WebKit 환경에 한정된다.

Firefox는 실행 환경 문제로 미검증이다. 실제 iPad Safari와 학교 Wi-Fi에서도 미검증이다. 다음 재현은 같은 기기에서 학교 Wi-Fi와 휴대폰 핫스팟을 번갈아 사용해, 재생 시작과 사진 저장 성공 여부를 따로 기록하는 게 좋다.
