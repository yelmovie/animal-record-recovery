# 반응형 화면 점검 및 개선 · 2026-10-23

## 확인 범위

실제 브라우저 렌더링을 다음 10가지 뷰포트로 확인했다. 수치는 브라우저 내부의 CSS 픽셀이다.

| 용도 | 화면 크기 |
| --- | --- |
| 세로 태블릿 | 768×1024 |
| 작은 가로 태블릿 | 906×755, 1024×768 |
| 가로 태블릿·노트북 | 1280×800, 1366×768 |
| 데스크톱 | 1440×900, 1920×900, 1920×1080 |
| 높이가 낮은 브라우저 | 1280×600 |
| 큰 화면·전자칠판 배치 | 2560×1440 |

기본 32개 상태 × 10개 크기 = 320회 측정: 시작, 마을, 18개 활동, 5개 주민 의뢰, 전시관, 인증서, 5개 보상 화면.

별도로 추가 의뢰·선택 도전, 12개 관찰 부위, 2D 대체 화면, 결과 정리, 빈 전시관, 오프닝·엔딩의 27개 상태를 906×755와 1280×600에서 확인했다(54회). 저장된 자유 발명과 사진 자료가 있는 전시관 다섯 방도 세 가지 크기에서 확인했다(15회).

설정·일기·개념 영상 창, 발명 단계 탭, 낮은 화면의 시험 결과 탭, 오답/정답 처리, 관찰 기록 후 크기 변경과 다음 부위 이동도 직접 조작했다. 사진 모음은 마우스 클릭과 키보드 Enter로 펼쳐지는 것을 확인했다. 테스트 저장은 별도 localhost 포트에서 사용해 사용자의 원래 저장 기록과 분리했다.

## 수정한 문제

- 관찰 사진이 고정 620px 확대와 유연한 패널 축소 때문에 얇게 잘리던 문제: 확대 영역의 최소 높이를 보장하고 사진·제목·설명과 선택지를 별도 행으로 배치했다. 넓은 화면에서도 사진의 부리를 확인하면서 세 선택지를 볼 수 있다.
- 방송 의뢰의 큰 동물 이미지와 반복 안내가 선택지 영역을 밀어내던 문제: 동물 소개와 세 질문을 두 열로 정리하고 선택지·탭의 조작 크기를 유지했다.
- 추리 노트와 생활 장면 기록의 과도한 높이: 단서 목록을 두 열로 배치하고 반복 문구와 사진 캡션을 정리했다. 세로 태블릿도 그림 영역과 노트 영역이 정해진 높이를 나눠 사용한다.
- 낮은 화면에서 시험 예상 답이 세로로 길어지던 문제: 세 선택지를 나란히 두고 모형을 옆에 배치했다. 결과 탭의 두 그림도 화면 높이에 맞췄다.
- 자유 발명 노트와 소개 양식의 높이: 보조 안내는 펼쳐 읽고, 낮은 화면에서는 소개 양식을 두 열로 배치한다.
- 전시관 탭 줄바꿈, 세로 화면의 전시물 겹침, 화면 밖 저장 버튼: 전시물·설명·하단 행동에 높이를 나누고 긴 내용은 해당 읽기 영역에서 스크롤한다. 사진 모음은 기본 접힘 상태로 열어 볼 수 있다. 고정 버튼이 사진 모음 클릭을 가리지 않도록 폭도 조정했다.
- 작은 2D 관찰 부위 버튼: 최소 너비 48px을 적용했다. 한글 선택지와 탭은 단어 단위로 줄바꿈한다.

## 결과와 한계

- 기본 320회 측정에서 문서 가로 넘침 0건, 화면 밖 기본 조작 버튼 0건, 검사 대상의 43px 미만 버튼/입력 0건.
- 기본 활동 18개는 10가지 크기 모두 기본 상태에서 내부 스크롤 없이 표시됐다.
- 추가 54회와 자료가 있는 전시관 15회에서 가로 넘침·화면 밖 조작 버튼·작은 조작 영역은 발견되지 않았다. 전시관의 동물·작품 그림도 크기 부족으로 사라지거나 잘리는 문제가 없는지 별도 확인했다.
- 모든 콘텐츠의 스크롤을 막지는 않았다. 768×1024의 발명 의뢰는 45px, 1280×600의 추가 발명 의뢰는 50px 정도 내부 스크롤이 남는다. 긴 방송 원고·누적 일기·전시 기록·펼친 사진 모음·추가 도움말은 읽기 영역 안에서 스크롤한다. 낮은 화면 전시관은 그림을 숨기지 않기 위해 전시 기록 영역이 스크롤된다.
- 오답 안내가 길어지는 상태는 설명을 읽기 위한 소량의 내부 스크롤이 생길 수 있다. 기본 이동 버튼은 바깥에 유지된다.
- 화면 크기 시뮬레이션과 브라우저 조작 검증이다. 실제 태블릿의 손가락 입력, 전자칠판 펜·터치, Safari/기기별 브라우저, 교실 시청 거리까지 검증한 결과는 아니다.

## 후속 수정 · 큰 화면에서 전시 그림이 사라지는 오류

사용자 화면에서 완료 배지·기록·동물 이름은 보이지만 전시 동물 그림이 사라지는 현상이 확인됐다. 1920×1080에서 이미지 파일은 정상 로드됐으나 네 동물 그림의 렌더링 높이가 모두 0px이었다. 앞선 이미지 점검은 작은 화면에 집중되어 이 큰 화면 오류를 놓쳤다.

원인은 가로로 나란히 놓인 `figure`의 높이가 정해지지 않은 상태에서 자식 이미지에 `height: 0; flex: 1`을 적용한 것이었다. `figure`에도 컨테이너 높이를 지정해 그림이 남은 높이를 사용하도록 수정했다. 수정 후 1920×1080에서 개구리·게·오리·토끼의 그림 높이는 각각 약 179px이다. 작은 태블릿의 분류 전시 사진 영역도 넓혔다. 학습 완료 상태나 저장 기록은 변경하지 않았다.

9가지 크기(1920×1080, 1920×951, 1920×950, 1835×1000, 2560×1440, 1280×800, 906×755, 1280×600, 768×1024) × 전시실 5개 × 기본/사진·자유작품 보유 상태 2종을 재검증했다. 이번에는 스크롤·버튼 외에도 전시 이미지와 모형 SVG 자체의 실제 너비·높이 및 이미지 파일 로드를 확인했다. 측정 자료는 `output/responsive-20261023/gallery-image-regression.json`, 화면은 `gallery-desktop-fixed.png`다.
