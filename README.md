# 동물기록 복구작전 · 하루와 모리의 자연 탐험 (0.4.0)

초등 과학 ‘동물의 생활’ 학습 게임. 사람 탐험가 하루가 이미지 지도에 그려진 길을 따라 이동하고, 너구리 모리가 따라다니며 관찰과 기록을 돕는다. 다섯 장소마다 서로 다른 4개 활동을 진행한다.

## 실행

Node.js 20 이상, 외부 패키지 설치나 API 키 불필요.

```sh
npm start
npm run check
npm test
npm run build
npm run preview
```

개발 주소는 `http://127.0.0.1:4173/`. `npm run preview`는 `dist/` 배포본을 같은 기본 포트로 제공한다. 개발 서버가 열려 있으면 별도 포트를 지정한다. PowerShell 예: `$env:PORT='4174'; npm run preview`.

## 20개 탐구 활동

| 장 | 첫 탐구 | 다음 탐구 |
|---|---|---|
| 관찰의 숲 | 확대 렌즈로 개구리·게 6곳 관찰, 공통점·차이 비교 | 오리·토끼 6곳 관찰, 다른 특징 비교 |
| 분류의 정원 | 6종을 날개로 분류 → 이동 예상 → 기준 바꿔 비교 | 6종을 다리 네 개로 분류 → 새 기준과 비교 |
| 생태의 물가 | 3환경 발견, 움직임 재생·정지·장면 기록, 개구리 생활 연결 | 새 동물의 움직임 기록, 토끼 생활 연결 |
| 동물 찾기 안내소 | 부분 그림의 단서 수집→후보 줄이기→오리의 환경·생활 | 새 단서 수집→후보 줄이기→토끼의 환경·생활 |
| 발명의 공방 | 물갈퀴 관찰→오리발 설계→폭 변경·예상·두 시험 비교·설명 | 등딱지 또는 털을 활용한 발명→덮개 범위 또는 겹 변경·시험·설명 |

첫 발명은 물갈퀴를 이용한 오리발, 두 번째는 안전모 또는 방한 외투를 만든다. 같은 조건에서 한 부분만 바꾸고, 서로 다른 두 설정을 시험하여 비교한다. 예상이 틀렸다고 실패하지 않으며 관찰·예상·시험·비교·알게 된 점을 남겨야 한다. 시험은 정성적인 설명 모형이며 실제 물리 성능·안전성 측정이 아니다. 펜 스케치와 글의 내용은 자동 채점하지 않는다. 친구와 설명·질문·의견 교환을 함께 운영한다.

## 역할과 보상

- 하루: 학생을 대신하는 탐험가. 지도 길의 실제 경유점을 따라 이동한다.
- 모리: 하루를 따라가는 기록 보조원. 실제 수집 기록을 수첩과 도구에 보여 준다.
- 검증한 활동당 탐험 별 1개, 최대 20개. 반복 클릭이나 속도로 추가 점수를 얻지 않는다.
- 장소를 복구하면 관찰 렌즈·분류 나침반·서식지 수첩·특징 스캐너·발명가 배지를 받는다.
- 도구를 가방이나 활동 화면에서 꺼내 다음 탐구에 사용한다. 모은 동물 카드 7종과 두 발명이 최종 결과에 반영된다.

## 교육과정과 화면 검증

[4과02-01] 관찰·특징 분류, [4과02-02] 환경과 생김새·생활 관계, [4과02-03] 특징을 활용한 생활용품 설계·협력적 소통과 연결했다. 협력적 소통은 실제 교실 대화와 교사 관찰을 함께 확인한다. 상세 근거와 화면별 검증 범위는 [태블릿 탐구 QA](docs/reviews/TABLET-INQUIRY-QA-20261016.md)를 참고한다.

## 저장과 이전 기록

현재 브라우저 LocalStorage에 자동 저장한다. 주소·포트·브라우저가 다르면 기록도 분리된다. 학생 이름·학번을 수집하거나 기록을 서버로 보내지 않는다.

0.3 저장 형식과 기존 별·완료 기록은 유지하며 새 관찰·시험 필드만 추가한다. 기존 완료 기록을 취소하거나 새 활동을 했다고 가정하지 않는다.

0.2 버전 기록은 보관하고 확인 가능한 첫 관찰·분류·환경 탐구만 이관한다. 새로 늘어난 활동과 바뀐 4장은 직접 해야 한다. 이전에 열렸던 장소의 입장 권한을 유지한다. 전체를 처음부터 보려면 탐험 가방 → 탐험 기록 초기화에서 확인 후 시작한다.

통과한 동물 안내 카드와 발명은 별도 제출 기록으로 보관한다. 다시 탐험하며 초안을 바꿔도 미검증 초안으로 최종 결과가 덮어써지지 않는다. 시험과 설명을 다시 마치면 성공 기록이 갱신된다.

## 주요 파일

- `src/inquiry.js`: 비교 시험·움직임 장면·단서 기록의 정규화와 판정
- `src/inquiry-views.js`, `src/inquiry.css`: 설명 모형·비교 시험 화면과 태블릿 레이아웃
- `src/expedition.js`: 20활동 콘텐츠·판정·보상·저장 이관
- `src/adventure-app.js`: 실제 입력·화면 이동·저장·스케치·내보내기
- `src/mission-views.js`, `src/shell-views.js`: 활동·지도·보상·가방 화면
- `src/trail-map.js`: 이미지 지도에 맞춘 경유점과 하루·모리 이동
- `src/presentation.js`, `src/assets.js`: 2D 이미지 경계. 이후 3D 교체 위치
- `src/adventure.css`: 실제 로드하는 공통 디자인·반응형 스타일
- `assets/adventure/`: 새 이미지 7종의 PNG 원본·WebP
- `docs/ADVENTURE-PLAN-20261015.md`: 이번 활동·역할·보상 설계
- `docs/ADVENTURE-ASSET-PROMPTS.json`: 실제 생성 프롬프트
- `docs/reviews/ADVENTURE-QA-20261015.md`: 이번 검증 결과

`src/model.js`는 이전 저장 정규화와 발명 판정에도 사용한다. 기존 `app.js`, `hub.js`, `style.css`, `polish.css`는 이전 버전 보관용이며 현재 화면과 배포에서 로드하지 않는다. `tests/app.test.mjs`는 이전 버전 회귀, `tests/adventure-app.test.mjs`와 `tests/expedition.test.mjs`는 현재 버전 검증이다.

## 빌드와 전달

`npm run build`는 실행에 필요한 파일만 `dist/`에 복사하고 CSS 이미지 경로를 확인한다. 이전 빌드 매니페스트에 기록된 미사용 실행 파일만 정리하며 원본·사용자 파일을 삭제하지 않는다. PNG 원본·테스트·문서는 배포 ZIP에서 제외한다. 정적 호스팅에 `dist/`의 내용만 올린다.

외부 배포는 실행하지 않았다. 실제 교실 기기·학생 사용·교사 내용 검수는 별도 확인 사항이다. 외부 패키지나 웹폰트·학생 계정·실시간 3D·영상은 추가하지 않았다. 이미지 생성 고지와 제공 자료 출처는 설정과 `assets/CREDITS.md`에서 확인할 수 있다.
