## 2026-11-17 3장 생활 잇기를 3D 길로 (개구리의 생활 · 게의 생활)

3장은 영상 보고 사진 찍기 두 번(`3-0` 첫 동물 세 마리, `3-1` 새 동물 세 마리)으로 여섯 동물을 모두 기록한 뒤, 3D 길 두 개(`3-2` 개구리의 생활, `3-3` 게의 생활)를 지나고, 마지막으로 여섯 동물이 함께 나오는 3D 「세 곳 이어달리기」(`3-4`)로 끝난다. 생활 잇기는 카드 끌어 놓기 대신 3D 길에서 한다.

- **세 곳 이어달리기(`3-4`)**: 숲과 들 길 → 연못 물길 → 꽃밭 위 하늘길 → 바다와 갯벌 길. 구간마다 내가 찾은 동물 중에서 그곳에서 만났고 그 길을 지나갈 수 있는 동물을 골라(카드에 내가 찍은 사진이 붙는다) 직접 지나간다. 판정은 3장 자료(`DISCOVERIES`·`MOTIONS`)만 쓰고, 기록은 `relay: {picks, done}`. 3D를 못 여는 기기에서는 맞는 동물을 고르면 그 구간을 바로 지나간다. 이전에 3장을 끝낸 기록은 완료 상태 그대로다(새 활동만 열려 있다).
- **방송 원고**: 3장 의뢰에서 동물 한 마리의 원고를 다 맞게 채우면 바로 넘어가지 않고, 「방송 들어보기」로 끝까지 듣거나 「들었어, 다음으로」를 눌러야 다음 동물로 간다. 계획과 결과는 [3D 달리기 스테이지 문서](docs/RUN-STAGE-3D-PLAN-20261117.md).

- **조작**: 화면 방향판(왼쪽 아래)과 방향키·WASD. 카메라는 돌리지 않는다. 목숨·시간 제한·점수가 없다.
- **3D를 못 여는 기기**(WebGL 없음, 주소에 `?2d`, 실행 중 3D 끊김): 원래 카드 화면이 그대로 나온다. 3D가 되는 기기에서는 카드 화면이 보이지 않는다.
- **이어달리기 위치**: 처음에는 선택 도전(지도 버튼)이었으나, 3장 마지막 필수 활동으로 옮겼다.

## 공용 태블릿에서 기록 보관·초기화

기록은 그 태블릿의 그 브라우저에만 자동 저장된다(서버 전송·로그인 없음). 주소·브라우저가 바뀌면 이어지지 않는다.

1. **보관**: 전체 탐험 기록을 내보내거나 가져오는 기능은 제공하지 않는다. **작품 저장 / 그림과 소개 저장하기**는 그림과 소개를 PNG로 저장한다. 전시관의 관찰 사진과 탐험 기록은 이 기기의 브라우저에서 다시 볼 수 있다.
2. **초기화**: 설정(오른쪽 위 톱니) → 아래 **탐험 기록 초기화** → 확인 창에서 한 번 더 확인. 장소 복구·관찰·그림·글이 모두 지워지고 되돌릴 수 없다. 소리 설정은 남는다.
3. 브라우저의 사이트 데이터 삭제·시크릿 창 종료도 기록을 지운다. 수업 시연용 **전체 단계 해금**(설정 → 교사용 가이드 → 교사용 도구)은 학생 기록을 바꾸지 않고, 끄거나 새로고침하면 원래 기록으로 돌아온다.

## 2026-11-13 생태 돔과 공통 화면 로딩 개선

관찰 화면은 포스터부터 표시하고 재생 또는 탐색을 요청할 때 영상을 받는다. 촬영한 순간을 확인하는 동안 같은 영상과 프레임을 유지한다. 화면 이동 시 불필요한 저장을 줄이고, 공통 글꼴·배경과 생태 돔 텍스처에 웹용 사본을 사용한다. 생태 돔은 선택한 동물부터 준비하고 나머지 모형을 차례로 불러온다.

Mac Chrome에서 5Mbps·지연 80ms로 제한한 로컬 빌드본을 비교했다. 토끼 영상 재생을 눌러 촬영이 가능해지기까지 1280×800 4.9초→3.7초, 1024×768(그림 화면) 6.2초→4.8초였다. 촬영 후 같은 영상 재요청은 두 화면 모두 1회에서 0회가 됐다. 첫 화면 주요 이미지 표시 시간은 약 2.6초로 비슷했다. 관찰 영상 8개의 합계는 10.2MB→5.0MB다.

Mac 문법 검사, 자동 테스트 276개, 빌드를 통과했다. 격리된 Chrome 기록으로 필수 동물 6마리 촬영, 두 연결 활동, 새로고침 후 기록 보존, 영상 지연 시 그림 관찰 전환을 확인했다. 실제 교실망과 iPad Safari·Android Chrome 실기기 및 Windows는 미검증이다. 측정과 화면은 `output/load-speed-20261113/`에 있다.

## 2026-11-15 탐험의 반복 조작 줄이기

분류의 정원에서는 이미 날개가 있는 칸에 놓은 닭·박쥐의 분류 결과를 표지판에 반영한다. 생태의 물가에서는 발견한 장소가 방송에 이어지고, 네 동물에서 몸의 특징과 움직임을 한 번씩 연결한다. 낙타·펭귄의 환경 비교 두 문제까지 포함해 방송 선택은 14번에서 6번으로 줄었다. 기존 동물 사진 여섯 장과 촬영 시점은 그대로 전시한다.

동물 찾기 안내소에서는 물가에서 완성한 개구리·게 관계를 전시 의뢰에 재사용하고, 벌·달팽이를 비슷한 동물과 구별하는 근거와 단서 부족 문제를 남겼다. 필요한 기록이 없는 이전 저장에서는 빠진 항목을 직접 답할 수 있다. 이미 전시한 기록은 유지한다.

교사용 자동 진행, 정답 후 자동 전환, 복구 후 주민 음성과 지도 복귀, 공방 마지막 도전 등 기존 진행은 유지한다.

Mac에서 문법 검사, 자동 테스트 279개, 빌드를 통과했다. 새 로컬 Chrome 기록으로 첫 화면부터 다섯 장소 복구와 개인 전시관까지 완료했다. 1280×800·1024×768에서 방송과 전시 흐름을 확인했다. 실제 학생의 흥미·수업 소요 시간과 iPad Safari·Android Chrome 실기기 터치는 미검증이다. 화면과 실행 기록은 `output/pace-review-20261114/`에 있다.

## 저장과 이전 기록

현재 브라우저 LocalStorage에 자동 저장한다. 주소·포트·브라우저가 다르면 기록도 분리된다. 학생 이름·학번을 수집하거나 기록을 서버로 보내지 않는다. 공용 기기 보관·초기화 절차는 위 ‘공용 태블릿에서 기록 보관·초기화’를 따른다.

2026-10-21 저장에 `observeTries`(관찰 문제별 처음 정답/도움 후 정답)를 더했다. 저장 형식 번호는 그대로이고 없는 필드는 빈 값으로 읽어서, 이전 저장의 진도·그림·글은 그대로 열린다. 이 필드가 없는 관찰은 ‘모름’으로 센다.

저장 형식 v5(2026-11-17)는 3장 순서를 사진 → 사진 → 개구리 → 게로 바꾸면서, v3·v4 기록의 3장 완료 표시 `3-1`(개구리)과 `3-2`(사진)를 서로 바꿔 옮기고 이어 할 활동 위치도 맞춘다. 완료한 장소와 관찰·사진·잇기 기록은 그대로다.

저장 형식 v4는 v3 기록을 이관하고 작품별 초안과 완료본을 분리한다. 분류 반복 축소로 없어진 두 활동을 제외한 기존 활동 완료 기록은 유지한다. 기존 완료 기록을 취소하거나 새 활동을 했다고 가정하지 않는다.

0.2 버전 기록은 보관하고 확인 가능한 첫 관찰·분류·환경 탐구만 이관한다. 새로 늘어난 활동과 바뀐 4장은 직접 해야 한다. 이전에 열렸던 장소의 입장 권한을 유지한다. 전체를 처음부터 보려면 탐험 가방 → 탐험 기록 초기화에서 확인 후 시작한다.

통과한 동물 안내 카드와 발명은 별도 제출 기록으로 보관한다. 다시 탐험하며 초안을 바꿔도 미검증 초안으로 최종 결과가 덮어써지지 않는다. 새 의뢰의 전시 기록은 최초 검증 제출본을 보존하며, 재풀이로 중복 보상을 주지 않는다.

## 빌드와 전달

`npm run build`는 실행에 필요한 파일만 `dist/`에 복사하고 CSS 이미지 경로를 확인한다. 이전 빌드 매니페스트에 기록된 미사용 실행 파일만 정리하며 원본·사용자 파일을 삭제하지 않는다. PNG 원본·테스트·문서는 배포 ZIP에서 제외한다. 정적 호스팅에 `dist/`의 내용만 올린다.

기존 0.4 버전은 Cloudflare에 배포되어 있고, 이번 0.5 변경은 로컬 구현·검증·배포 파일 준비까지 수행했다. 실제 교실 기기·학생 사용·교사 내용 검수는 별도 확인 사항이다. 기존 로컬 three.js·GLB 표본·글꼴은 유지하며 학생 계정이나 외부 백엔드를 추가하지 않았다. 이미지 생성 고지와 제공 자료 출처는 설정과 `assets/CREDITS.md`에서 확인할 수 있다.
